# asm6x

An assembler for the TMS320C6000 — the C674x core of the C6747 — in C-style ISO C++14.
It takes the assembly the `c90`, `cpp11` and `shalimar` compilers write for their `tms6747`
target and writes the ELF object TI's own `asm6x` writes for it, which `lnk6x` links
against TI's runtime. It is the C6000 counterpart of [MASM](../MASM), the x86-64
assembler, and lives beside it rather than inside it.

TI's `asm6x` (CCS 7.4, C6000 CGT 8.2.2, on the Windows box) is the oracle. Every encoding
here was read back from it, one form per line — `tests/probes/probe1..6.s` are the probes,
`tools/forms.py` turns their listings into `src/forms.h` — and the tests hold every object
to it, table by table. A Fable 5.1 review of 2026-09-19 (`REVIEW-2026-09-19.md`, its 442
edge probes and link checks under `review-probes-2026-09-19/`) was mended in full; the
ledger is at the end of the review.

## Layout

```
src/asm.h          shared structs, Unit, the target, the writer, Assembler
src/lexer.cpp      a TI source line -> tokens (; comments, name in column 1 is a label, ||)
src/expr.cpp       constant expressions and TI's relocation operators ($EXIDX_FUNC and kin)
src/unit.cpp       sections, symbols, emission, fixup resolution
src/c6x.cpp        directives, operands, the instruction encoder
src/forms.h        the register, constant and pair forms, generated by tools/forms.py
src/elf.cpp        the TI ELF writer
src/compact.cpp    --compress: the 16-bit forms and header-based fetch packets
src/assembler.cpp  one job: read, assemble until the layout settles, resolve, write
src/main.cpp       command line, one thread per input file
tests/             tests/run.sh (python3 only), tests/windows.sh (the box), tests/probes
tools/forms.py     regenerates src/forms.h from tests/probes/*.{s,dis}
```

## Build

```
mkdir -p build && c++ -std=c++14 -O2 -pthread -Wall -Wextra -pedantic src/*.cpp -o build/asm6x
```

## Use

```
asm6x file.s -o file.obj
asm6x a.s b.s c.s              each on its own thread, a.obj b.obj c.obj beside them
```

## What it encodes

The instruction word is `creg z dst src2 src1 x form s p`. `src/forms.h` holds the ten
form bits of every register, constant and pair form asm6x assembled from the probes — one
row per mnemonic, unit, operand shape and cross path, with the field each operand lands in
and a mark on the rows asm6x chooses when the source names no unit; `src/c6x.cpp` encodes
the rest by hand from the same listings: the loads and stores (constant offsets in units
of the access or in bytes, register offsets, the pre- and post-increments, the 15-bit
offsets from B14/B15), `MVK`/`MVKL`/`MVKH`/`MVKLH`, `ADDK`, `B`/`CALLP`/`BNOP`/`RET`/
`RETNOP`, `NOP`/`SWE`/`IDLE`, `MVC` with its control registers, `ZERO`, the four-operand
field instructions, the 15-bit address adds from B14/B15.

A unit may be named (`ADD .L1X B1, A2, A3`, `LDW .D1T2 *A4, B6`); when none is, the unit
is asm6x's own default, read back from it: register `ADD`, `SUB` and `MV` go to `.D`
(the C64x+ `.D` forms when a source crosses), `AND`/`OR`/`XOR`/`NOT` to `.D`'s C64x+
forms, the compares to `.L`, shifts, `NEG`, `MVK` outside -16..15, branches and the field
instructions to `.S`, `MVK` of -16..15 and `ZERO` to `.L`, multiplies to `.M`. In an
execute packet (`||`) two instructions wanting one unit are told apart as asm6x tells
them: the later one moves to a free unit it has a form on, in the order D, S, L, M, or an
earlier one makes way for it. asm6x's rewrites are followed too: `ADD r, -c` is the `.D`
signed form up to -16 and `SUB r, c` beyond it, `SUB r, -c` is `ADD r, c`, a crossed first
source of a commutative operation is swapped, of a compare turned about, of `SUB` given
the `.S` form that takes it (or `.L`'s crossed-first form when `.S` is taken), and a
constant written after the register of a compare is the constant-first compare of the
other sense. A branch to a label of its own section is settled in place, in words from the
fetch packet holding it; every other reference is a relocation of the kind asm6x writes —
`ABS_S16`/`ABS_L16`/`ABS_H16` as RELA entries with the half in the field too, the rest REL
with the addend in place (in the displacement field of a `B`/`CALLP`, `PCR_S21`, or `BNOP`,
`PCR_S12`), `$` and the marker on a data word ending a code section against the section's
own symbol.

Where asm6x warns and mends, so does this, with the same value: a `MVK` outside 16 bits
wraps, `NOP 10` is 9, `.byte 256` is truncated, `.align 3` is 4, an offset that is not a
multiple of the access is cut, a number past 64 bits wraps. Where it refuses, so does this:
`CALLP` with a predicate or a return register other than A3/B3, a long operand across the
cross path, an alignment over 32K, a label not in column 1, `||` after a label, a
predicate or a section switch, `.set` with its name in the operand field, a forward
constant in a directive that sizes a section.

Directives: `.text`, `.data`, `.sect` (quoted or not, `RW` for a writable one), `.bss`,
`.usect`, `.global`, `.def`, `.ref`, `.weak`, `.align` (alone: 1), `.word`/`.long`/`.int`/
`.ulong`/`.uint`/`.uword`, `.half`/`.short`/`.uhalf`/`.ushort`, `.byte`/`.char`/`.ubyte`/
`.uchar` (a string is one item per character), `.string` (raw), `.cstring` (C's escapes,
`\ooo` too, `\x` dropped as asm6x drops it, no second NUL after `\0`), `.float`, `.double`,
`.space`, `.bes`, `.set`/`.equ` with the name in the label field (a constant, or an alias
of a label that stands for the label), `.asg`, `.symdepend` (one operand or two, the
section named before it is opened), `.end`, and the ones that change nothing (`.clink`,
`.retain`, `.nocmp`, `.compiler_opts`, `.file`, `.list`, `.title`, `.option`, `.length`,
`.width`, `.battr`, `.elfsym`, `.hidden`). Expressions have `+ - * / % << >> & ^ | ~`,
`$`, decimal, `0x`, `0` octal, `FFh`, `17q`, `1010b`, `'a'` and `''''`. A section is what
its content makes it: loaded and read-only unless `.data` or `RW`, executable, 32-aligned
and padded to 32 once an instruction lands in it, uninitialised only by `.bss`/`.usect`.
A `.word` or `.half` aligns its section as TI's do; a `.bss` symbol carries its size when
global, a `.usect` symbol always.

The object: `.text` first, the source's sections in order, then `.c6xabi.attributes` (the
bytes asm6x writes for `--abi=eabi -mv6740`, which lnk6x checks a file against),
`.symtab`, the exidx tables (each linked to the code section its name ends with), the
relocation sections in the order the source first needed them, `.TI.symbol.alias`,
`.TI.section.flags`, the string tables. Every symbol is `STV_HIDDEN`, as asm6x marks
them; a `.global` of a symbol neither defined nor used is not written, a `.def` of one
not defined is refused.

Not done, and not asked of it by the compilers: DWARF, `ADDKPC`, `.field`, macros. The
compact 16-bit instructions asm6x writes by default are `--compress` here, below, and off
unless asked for. Where asm6x itself fails — a difference of two labels it has not both placed
(its "relocation template 275 not found"), `%`, an exidx table holding a byte, an
operator alone or in an instruction — this one does the sound thing instead;
`review-probes-2026-09-19/known.txt` lists those eleven probes, and `labeldiff/`
holds the six label differences to what TI's dis6x and lnk6x said of ASM6x's
objects, since asm6x's own word is not to be had for them.

## Compression: `--compress`

`asm6x --compress file.s` lays each code section out as asm6x does by default: 16-bit
instructions two to a word in header-based fetch packets. The header is the packet's last
word - 0xE in its top nibble, which of the other seven words hold two halves (the low half
first), PROT, DSZ, BR and the halves' p-bits; a 32-bit word in such a packet keeps its own
p-bit. The object is otherwise the one the plain layout gives: the labels, the relocations,
the exception tables' scope differences and the unwind index move with the code.

Every rule was read from asm6x 8.2.2's objects - its compressed object set beside its
`--no_compress` one for the same source, instruction for instruction, over the review's
347-file corpus, the Compiler++ harness at -O1 and -O2 and bench-c6x (300,000 compact
instructions): `src/compact.cpp` makes, for each one, the 16-bit word asm6x made. The forms:
`NOP n` (1-8); `LDW`/`STW`/`LDB(U)`/`LDH(U)`/`STB`/`STH`/`LDDW`/`STDW` with `*+R[k]`, R one
of A4-A7/B4-B7, k 0-15, under the header's DSZ; `LDW`/`STW *+B15[0..31]`; `ADD`/`SUB .D2
B15, 4k` as `ADDAW`/`SUBAW` (and `ADD .D2 B15, 4k, B0-B7`); `ADD`/`SUB`/`XOR` of 1 to itself
and `ADD`/`SUB` of two registers into the first on `.D`; `MV` (`OR 0`, `ADD 0`) either way
across the three bits; `MVK .S` 0-255, `MVK .L` -16..15; `B`/`BNOP` of a B register;
`B`/`BNOP` of a label within 64 halfwords of the fetch packet (BR=1); `NEG .S`; `EXT`/`EXTU`
16,16 and 24,24; `SHL`/`SHR`/`SHRU` by a constant or a register; `CMPEQ` of 0-7 and the five
compares of two registers into A0/A1 or B0/B1. A register above 7 on the three-bit fields, a
predicate, a relocation, a cross path a form has no bit for - the instruction stays 32-bit.

The layout is asm6x's where it could be read: one fetch packet at a time from the first
instruction, the header's context that takes the most instructions (tried with PROT last,
BR before it, DSZ counting up; a plain packet only where it takes more, or where fewer than
eight instructions are left), 16-bit instructions paired greedily in their order, a NOP 4
after a load dropped under a PROT header, a label a 32-bit branch reaches kept on a word, and
the whole redone until nothing moves. A 32-bit `BNOP` in a header-based packet counts its
displacement in halfwords, and resolve() does so. What asm6x does that this does not: the
high register set (RS=1), CALLP and the other compact branches (`tests/compact/learn` asks
asm6x about them), and asm6x's own history for a forward branch on the edge of 64 halfwords -
so of the 347 corpus files, 273 come out as asm6x's object table for table, every code byte
included; the rest are as small (1,838,592 bytes of code against asm6x's 1,838,944) and differ
in which branches are 16-bit. Where anything could go wrong the rule is the safe one, and the
finished layout is checked against the machine's rules before it is written - a label on a
word where a 32-bit branch reaches it, every compact branch in range, every load of a PROT
packet followed by the NOP it stands for, a PROT NOP dropped only when no branch is in flight
and no label names it; a section that fails, or that holds data or `.align` among its
instructions, stays as it was. Without `--compress` nothing changes: every object is the one
the previous version wrote.

Held to three things. `tests/compact/verify.py` disassembles the plain and the compressed
object with binutils' objdump for tic6x (`tools/build-tic6x-objdump.sh`) or reads dis6x's
listings of them, and requires the same instructions in the same order and execute packets,
every PROT-dropped NOP 4 accounted for, the same branch targets and the same symbols:
`sh tests/compact/check.sh` runs it over tests/compact, and over any directory named - 1,075
files on 2026-09-30 (tests/compact and its learn/, the review's corpus, and cpp11's own -O1
and -O2 output for the six kernels and every tests/cases program, which
`tests/compact/cpp11-corpus.sh` writes), all passing; it passes asm6x's own compressed objects
too (the corpus, the harness at -O1 and -O2, bench-c6x), its RS=1 packets held to the mnemonic
only. On the box, `sh tests/windows.sh compact` holds ours to asm6x's compressed objects
table by table and byte for byte and has dis6x list both; and TI's simulator runs the kernels
assembled so (`ASM6X=<this tree>/tools/asm6x-compress tools/c6747-levels` from C++Optimize).

## In RIDE

RStudio's workspace builds `asm6x.exe` into its `bin` beside `vm6747.exe` (make-projects.py
knows it as the sixth product, on all three machines). Every project build for `tms6747`
then assembles the `.vm` directory's assembly into TI objects, and with TI's C6000
compiler directory named (Tools > TI compiler for tms6747..., or `--ti dir [--tilib dir]`)
lnk6x links them against TI's runtime into `<program>.out`. TriLab's CCS leg says
`RIDE-OUT` for its C and C++ labs.

## Tests

`sh tests/run.sh` assembles `tests/enc/*.s` and compares each object with the one asm6x
wrote for the same file (`*.asm6x.obj`, recorded by `sh tests/windows.sh record`): the
sections, every code word, every data byte, the relocations and the symbols, by name;
then the review's 442 edge probes, link checks and fresh compiler files the same way,
against the objects asm6x wrote for them (`review-probes-2026-09-19/recheck.sh`).
python3 only, so it runs on all three machines.

`sh tests/windows.sh <dir>` ships a directory of `.s` to the box, has asm6x assemble
each, assembles each here, diffs every pair, then links ours with lnk6x against
`rts6740_elf_eh.lib` (`WITH=<dir>` adds a runtime's objects to every link, for shalimar's
programs). On 2026-09-19, after the review: c90 403 of 403 identical and linked, cpp11
302 of 302, shalimar 58 of 58 with 57 linked — the one that does not borrows `cbrt`, which
TI's runtime lacks; the cl build on the box writes the same objects as the clang build;
all 763 on 763 threads in one invocation under ThreadSanitizer, byte-identical to the
one-at-a-time objects; every probe under AddressSanitizer and UBSan, clean.
